# 给后端：前端静态文件会不会由后端的 admin 应用提供；安全响应头加在哪些响应上

> **写给：** AvatarBackend 会话（后端）。
> **来源：** 管理端前端。后端清单 `docs/backend-inputs/2026-10-29-avatar-backend-d1-admin-frontend-changes.md` 第 4 节第 10 条写明：把"公开文件路由的安全响应头"（`item-06.md`）列为不改变管理端，依据是我们的计划写了前端用同域反向代理；但"没有核实管理端的静态文件是否也可能由后端 admin 应用提供（若是，`Content-Security-Policy: default-src 'none'` 会影响页面本身）"。这个问题在管理端前端的仓库里核实不了（我们只读本仓库，看不到后端代码），所以问后端。
> **我们的做法（先按最小的继续）：** `docs/deploy.md` 的做法是：`npm run build` 的静态文件由反向代理（或别的静态文件服务器）在和后端同一个域名下提供，`/api/` 转发给后端，其余路径回退到 `index.html`；后端的 admin 应用不提供前端的静态文件。部署文档已经写明"不要让后端的 admin 应用提供前端静态文件"，直到下面的问题有了答复。

## 问题

1. **后端的 admin 应用有没有任何会返回前端页面（HTML、脚本、样式、图片）的路由或静态资源配置？** 例如把前端构建产物放进后端的静态资源目录、或有一个回退到 `index.html` 的路由。如果没有，请回复"没有"，我们就可以把部署文档里的这条限制改成事实陈述。如果有，请说明路径和它的响应头。
2. **那组安全响应头（清单说六个，来源 `item-06.md` 第 7–16 行）具体是哪六个、值是什么、加在哪些响应上？** 清单写的是"后端把这六个响应头加在 admin 的每个业务端口响应上（`item-06.md` 第 11 行）"，标题却是"公开文件路由的安全响应头"。我们需要知道：
   - 六个头的名字和值（清单只点名了 `Content-Security-Policy: default-src 'none'`）；
   - 是只加在公开文件路由上，还是加在 admin 业务端口的每一个响应上（包括 `/api/admin/**` 的 JSON 响应）；
   - 反向代理在 `/api/` 上是否还需要补任何一个。
   原因：反向代理的 `add_header` 不会去掉后端已经加的头，会再加一个，同一个头在响应里出现两次；示例配置里的 `/api/` 现在只加 `Cache-Control`，已经用 nginx 1.24 实测过，不会重复这些头。如果后端并没有给 `/api/admin/**` 加这些头，反向代理就应该补，我们需要知道该补哪些。
3. **后端有没有给 `/api/admin/**` 的响应设 `Cache-Control`？** 示例配置在 `/api/` 里加 `Cache-Control: no-store`（接口响应里有个人数据和签名地址）。如果后端自己也发这个头，响应里会有两个值；如果后端已经发了合适的值，我们就把反向代理这一行去掉。

## 为什么需要

- 问题 1 答案是"有"时，`Content-Security-Policy: default-src 'none'` 作用在前端页面上，脚本和样式都加载不出来，页面白屏。
- 问题 2、3 影响 `docs/deploy.md` 里的反向代理示例和"发布后的检查"（我们让部署的人用 `curl -i` 确认每个安全头和 `Cache-Control` 在 `/api/` 响应里只出现一次）。
