# 给后端的问题：短信渠道 `credentials` 是“名称到文本值”的映射吗，各供应商要哪些名称

> **写给：** AvatarBackend 会话（后端）和改契约的会话。
> **来源：** 管理端前端处理后端清单 W2a 的第一条：“短信渠道 `POST/PUT /api/admin/sms/channels`：`credentials` 的值必须是非 null 字符串（值为 null 或名称为空 → 400 `EMPTY_NOT_ALLOWED`，`ref` 为 `credentials`）；不改凭据时省略该字段或发 `{}`”。
> 之前的问题文件 `2026-10-26-admin-frontend-sms-email.md` 第一节第 1 条里，前端暂定 `credentials` 是**一个字符串**（页面里一个密码框），并请后端“如果要结构化的值，请说明形状”。W2a 的写法（“值”“名称”“`{}`”）说明后端收的是映射，所以前端已改成映射，下面的几点请后端确认。

## 前端现在怎么做

- 渠道对话框里的“凭据”是若干行“名称 + 值”（值是不可显示的密码框），没有预填：已保存的凭据**永不回显**，打开编辑时一行也没有。
- 请求体：至少有一行完整（名称和值都不空，去首尾空白）时，发 `"credentials": {"<名称>": "<值>", …}`；没有行或行都留空时**不带这个键**。名称在页面里不允许重复、不允许只填一边；所以页面本身不会发出 null 值或空名称。
- 有条目的映射**替换**全部已保存的凭据（页面文字写明：要把每个名称和值重新填一遍）。

## 请后端确认

1. `credentials` 是否就是 `{"名称": "文本值"}` 的一层映射？值只能是文本吗（数字、布尔要不要）？
2. 有条目的映射是**整体替换**已保存的凭据，还是**按名称合并**（只改带来的名称）？前端现在按整体替换写提示；若是合并，提示要改，并且要有“删除某个名称”的办法。
3. 每个供应商（`GET /sms/meta` 的 `providers[].code`）需要哪些名称？现在页面让运营自己输入名称，容易拼错。请求：`GET /sms/meta` 的每个供应商增加 `credentialNames`（字符串数组），页面就改成固定名称、只填值。
4. 收到字符串（旧写法）时后端的反应是什么（400 哪个码，`ref` 是什么）？前端不再发字符串。
5. 名称的长度、字符集和条数上限，值的长度上限（页面现在不限）。
6. “值为空串”是否允许？页面不发空值（只填名称的行会在页面里被拦下）。

**暂定做法：** 如上；假后端对 null 值、空名称（含只有空白的名称）、非映射（null、文本、列表）答 400 `INVALID_REQUEST`，`details` 为 `[{"ref":"credentials","reason":"EMPTY_NOT_ALLOWED"}]`。
