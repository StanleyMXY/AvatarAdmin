# 给后端的问题：总览页里契约没写清的四处

> **写给：** AvatarBackend 会话（后端）和改契约的会话。
> **来源：** 管理端前端任务 21（总览 `/dashboard`）。下面四处契约 §17.6 和后端的回复里都没有写清，前端和假后端按"暂定做法"先做，后端回复后再改。这些不阻塞页面。

## 一、当天还没有汇总行时 `/stats/daily` 怎么返回

契约写"当天的行是临时值，次日起固定"，补数每隔 `stats.land_interval_minutes` 分钟刷新当天；没有写：UTC 零点之后、第一次落地之前，`/stats/daily?from=<今天>&to=<今天>` 是不返回今天这一行，还是返回一行各列为 0 或 `null` 的行。

**我们为什么需要：** 总览的六张卡片都以"今天"的值为当前值。没有这一行时，卡片应该显示"—"（不知道），而不是 0（今天真的没人）；两种返回对应两种显示。趋势图上，过去的日子没有行补 0（规格 4.4），今天没有行则留空。

**暂定做法：** 今天没有行，或者某一列是 `null`，都当作"还不知道"：卡片显示"—"，不标"临时值"，较昨日、较 7 天前也显示"—"；趋势图今天这一点留空。今天的行里某列是真正的 0，显示 0。

## 二、昨天的 cohort 的 `d1` 什么时候有值、是不是临时值

契约写"落地时对日期 `D` 填 `cohortDate = D − N` 的格子"，也就是昨天这个 cohort 的 `d1` 在今天（`D`）落地，而今天的落地每隔 `stats.land_interval_minutes` 分钟刷新、到次日才定稿。契约没有写：今天第一次落地之前，昨天 cohort 的 `d1` 是 `null`，还是 0；今天落地之后、今天结束之前，它是不是临时值。

**我们为什么需要：** D1 留存卡取 `ACTIVE` 类型里最新一个 `d1` 非空的 cohort。如果 `d1` 在落地之前返回 0 而不是 `null`，卡片会显示"0%"，被读成"昨天注册的人一个也没回来"。另外，今天落地的 `d1` 如果是临时值，卡片要标"临时值"。

**暂定做法：** `d1` 为 `null` 才算没有值，0 是真的 0；`cohortDate` 加一天等于今天（UTC）的那个 cohort，它的 `d1` 标"临时值"，更早的 cohort 不标。

## 三、`GET /moderation/stats` 的 `oldestPendingSeconds` 和 `from`、`to` 有没有关系

契约写"当前最老待处理的等待时长"，同一个响应里还有按 `from`、`to` 统计的 `items` 和 `avgHandleSeconds`。没有写 `oldestPendingSeconds` 是否与 `from`、`to` 无关（现在最老的待处理记录，不论创建在哪天）。

**我们为什么需要：** 总览的"审核积压"卡片只要这一个数字，不要按日统计；为了让请求最小，我们把 `from`、`to` 都写成今天。如果它依赖范围（例如只在范围内找最老的待处理记录），卡片会漏掉更早创建、仍在等待的记录，显示偏小。

**暂定做法：** 按"与范围无关"处理，`from`、`to` 都传今天（UTC）。

## 四、`GET /alerts?status=OPEN&page=1&pageSize=1` 的 `total` 是不是全部未处理告警数

契约 §17.4 写后台告警接口分页（`{items,total}`），没有明写 `total` 在带 `status=OPEN` 时是满足筛选的总数，而不是当前页的条数。

**我们为什么需要：** 总览的"未处理告警"卡片只读 `total`，只取一条（`pageSize=1`）以免拉整页；如果 `total` 是当前页条数，卡片永远显示 1。

**暂定做法：** 把 `total` 当作满足筛选的总数；不是数字时卡片显示"—"。
