# 2026-11-03 后端实现说明与更新接口文档里查不到的细节（组 c2：17、19、22、45、46、60、61、134 号）

这份文件只记录查不到的细节；前端当前按下面写的最小做法开发，不是阻塞。契约快照不改。

## 1. 409 `INVALID_STATE` 的 `LAST_SUPER_ADMIN` 和 `CONCURRENT_CHANGE` 在什么情形下出现（22 号）

- 更新接口文档第 2392 行只写了三个值各自的含义和检查顺序（“对自己 409 → 最后一个启用的超级管理员 409”）。按这个顺序，一个请求一个请求地做时，`LAST_SUPER_ADMIN` 只会在操作者本身就是被操作的那个超级管理员时出现，而这时先命中 `SELF_PROTECTED`；所以我们理解为它和 `CONCURRENT_CHANGE` 都是并发时才见到的。
- 前端做法：页面只按 `data.reason` 选三句话，不推断；`reason` 缺失或不认识时只显示 `error.INVALID_STATE` 的文字。假后端用一个测试开关（`systemState.race`）让“对别的超级管理员的写”答这两种 `reason`，并保留 `data.status`。
- 请求：后端确认 `CONCURRENT_CHANGE` 会出现在哪几个接口（我们假设 `PUT`、`status`、`reset-password`、`reset-totp`、`DELETE` 五个都可能），以及带未改字段的 `PUT` 是否也可能。

## 2. `GET /me.roleIds` 对超级管理员（19 号）

- 后端实现说明只写“被分配的角色编号，按文本升序”。契约又写超级管理员不受“不能修改自己被分配的角色”限制。
- 前端做法：超级管理员的角色页不预先禁用“编辑”；其他人在 `roleIds` 里有的角色行禁用“编辑”并在行内写原因，“删除”不禁用（删除不受 `OWN_ROLE` 约束，仍分配的角色删除答 `ROLE_IN_USE`）。后端仍是最终裁决。
- 请求：后端确认超级管理员的 `roleIds` 是否也列出被分配的角色，以及“删除自己持有的角色”是否与 `ROLE_IN_USE` 之外还有别的拒绝。

## 3. 审计日志筛选取值的“其他（手动输入）”（45、46 号）

- 后端实现说明说已被淘汰的值不再出现在 `GET /audit-logs/meta`，但旧记录里仍可能有；已删除的管理员不在 `GET /audit-logs/admins`，旧记录仍有 `adminId`。
- 前端做法：下拉最后一项“其他”打开输入框（动作和对象类型 64 个字符，管理员编号 255 个字符，与后端的限制一致），保留旧值（例如一个保存下来的搜索）的显示。这是请求文件 2026-11-02-requests-to-backend.md 45、46 号写的做法，不是新功能。
- 请求：后端说明 64、255 的单位（字符、UTF-16 单位还是码点）；前端现在按 `maxLength`（UTF-16 单位）限制，基本平面之外的字符可能比后端的限制多算。

## 4. “未结束的删除”指哪几个状态（60 号）

- 更新接口文档第 2457 行写“该账号未结束的删除任务”，第 13.1 节写 `SCHEDULED`、`PENDING`、`RUNNING`、`FAILED` 时账号上只能有一条。
- 前端做法：假后端把这四个状态当作未结束；页面显示后端给的 `deletion.status`，状态词表里没有的值原样显示。`requestedBy` 为 `null` 显示“用户自己”；`requestedBy` 有值而 `requestedByUsername` 为 `null`（发起的管理员已被删除）显示“已被删除的管理员（编号前 8 位）”。
- 请求：后端确认 `FAILED` 是否算“未结束”（我们按算）。

## 5. 签名地址过期时刻与浏览器时钟（134 号）

- `expiresAt` 是服务器时钟的绝对时刻（UTC）；前端用浏览器时钟计算“离过期还有多久”。浏览器时钟偏差大时，重新取会偏早（多一条审计记录）或偏晚（播放器先失败一次，再由原有的“失败后重取一次”兜底）。
- 前端做法：过期前 30 秒（剩余时间不足 60 秒时取剩余时间的一半，最少 1 秒）重取一次；标签页不可见时不取，可见后再取；正在播放声音或视频时每 5 秒再看一次，停下后才换地址；重取失败时保留已显示的内容，不再自动重试。
- 请求：后端若愿意，可在响应里带服务器当前时刻（或让前端读 `Date` 响应头），前端就能用差值而不是浏览器时钟。不是必须。
