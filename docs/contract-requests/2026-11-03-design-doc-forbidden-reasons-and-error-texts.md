## 1. 第 26 行 错误处理表：403 `ADMIN_FORBIDDEN`

- **现在：** "403 `ADMIN_FORBIDDEN` 提示无权限、不跳转"（设计文档第 26 行）。
- **改成：** "403 `ADMIN_FORBIDDEN` 提示按错误码翻译的文字、不跳转、不退出登录；会话层重新读一次 `GET /me`（第 88 行）。系统管理里改角色和管理员的写操作被拒时，`data.reason` 说明是哪一条规则拦下的，见 5.16：已知的原因在码的文字后面加一句该原因的说明，缺少 `reason` 或不认识的值时只显示码的文字。"
- **前端现状：** `src/pages/system/texts.ts:37-42`（`withScopeHint`：`data.reason` 是六个已知值之一才加句子，否则原文不变）。
- **行为 / 检查顺序 / 错误：** 无新增接口和错误码；契约 2392 行列出的六个原因见第 4 条。
- **测试：** 收到带已知 `reason` 的 403 → 文字是"码的文字 + 原因句"；不带 `data` 的 403 → 只有码的文字；403 之后没有跳转、没有退出，`GET /me` 只重读一次。

## 2. 第 108、109 行 弹窗表单失败时显示什么

- **现在：** 第 108 行 "失败保持打开并展示后端 `message`"；第 109 行 "Java 返回 `INVALID_REQUEST` 时，`message` 写明是哪个字段，前端原样展示"。
- **改成：** 第 108 行："失败保持打开，展示按错误码翻译的文字，不附后端 `message`；错误码不认识时显示'未知错误'加后端 `message`。" 第 109 行："`INVALID_REQUEST` 带 `details` 时，在对应字段下展示按 `reason` 翻译的文字（`ref` 指向字段）；某条 `reason` 没有译文时，只有一条 `details` 就退回后端 `message`，有多条就退回 `reason` 代码本身。"
- **为什么：** 和同文件第 459 行已经写的做法一致（"用户可见的提示文字由前端按错误码映射，`message` 只作兜底"），也是负责人定的规则（界面只有简体中文和英文，`message` 是英文且可能随版本改动）；第 108、109 行是旧写法，和第 459 行矛盾。

- **测试：** 已知码的失败不出现后端 `message` 的英文句子；不认识的码出现"未知错误 (message)"；单条 `details` 的 `reason` 无译文时显示 `message`，多条时显示 `reason` 代码。

## 3. 第 357 行 角色（5.16）：自己被分配的角色、含有未持有权限的角色

- **现在：** 第 357 行只写了列表、新建、编辑、删除、权限树勾选规则，没有"操作者只能授出自己持有的权限"带来的页面行为。
- **补：**
  - **自己被分配的角色：** 非超级管理员不能修改自己被分配的角色。列表里这样的行"编辑"置灰，行内用小字写明"这个角色分配给了你自己，不能修改自己持有的角色。"（键盘和触屏也看得到，不靠悬停提示）。"删除"不置灰（后端决定：角色仍被分配时是 409 `ROLE_IN_USE`）。判断依据是 `GET /me` 的 `roleIds`；超级管理员不受限。后端仍是最终裁决：修改被拒 403 `ADMIN_FORBIDDEN`，`data.reason` 为 `OWN_ROLE`。
  - **含有未持有权限的角色：** 非超级管理员打开一个角色时，若角色里有他自己不持有的权限码（包括不是权限树节点的码），对话框顶部用警告写出这些码（最多 20 个，超过则写前 20 个加总数），保存按钮关闭。权限树里他不持有的节点显示但不能勾选或取消。勾选一个节点只带上他持有的后代和他持有的上级；他不持有的节点不会被别的节点的点击改变。"持有的权限码"取 `GET /me` 的 `permissions`；这只是辅助，不假定它和后端判断用的集合完全相等，后端仍是最终裁决（403，`reason` 为 `GRANT_NOT_HELD` 或 `ROLE_NOT_HELD`），页面按第 4 条显示。超级管理员不受限。
  - 保存按钮在权限树读出来之前关闭（没有树就无法不丢码地整体替换）。
- **前端现状：** `src/pages/system/roles.tsx:31-32,51-59,98-117`（自己的角色）；`src/pages/system/RoleModal.tsx:25-26,58-69,145,151-165`（未持有的码）；`src/pages/system/permissionTree.ts:177-205,236-244` 和 `PermissionTreeSelect.tsx:69`（树里的禁用和勾选规则）。

## 4. 第 356 行 管理员（5.16）：403 和 409 的原因

- **现在：** 第 356 行写了行操作和不能停用自己、最后一个启用的超级管理员不能被停用，没有说被拒时显示什么。
- **补：** "管理员和角色的写操作被拒时，界面显示'该错误码的译文，加该 `data.reason` 的一句说明'。一句说明跟随 `reason`，不跟随页面做的操作（同一个操作可能被不同规则拦下）。`reason` 缺失或不认识时只显示码的译文。"

  | 状态码和错误码 | `data.reason` | 说明的意思 |
  |---|---|---|
  | 403 `ADMIN_FORBIDDEN` | `GRANT_NOT_HELD` | 要授出的权限里有操作者自己没有的 |
  | | `ROLE_NOT_HELD` | 要修改或删除的角色里有操作者自己没有的权限 |
  | | `OWN_ROLE` | 这个角色分配给了操作者自己，不能修改 |
  | | `ADMIN_NOT_HELD` | 目标管理员持有操作者自己没有的权限 |
  | | `SUPER_TARGET` | 目标是超级管理员，只有超级管理员能对超级管理员操作 |
  | | `SUPER_FLAG` | 只有超级管理员能设置或清除超级管理员标志 |
  | 409 `INVALID_STATE` | `SELF_PROTECTED` | 对自己：改自己的角色或超级管理员标志、改自己的状态、删除自己 |
  | | `LAST_SUPER_ADMIN` | 最后一个启用的超级管理员不能停用、删除，标志也不能清除 |
  | | `CONCURRENT_CHANGE` | 同时有另一个对超级管理员的修改在进行，什么都没改变，稍后重试 |

  每句都以"什么都没有改变"结尾（`CONCURRENT_CHANGE` 的句子在其中提示稍后重试）。409 的 `data` 另有 `status`（目标管理员的当前状态），页面不依赖它。
- **管理员对话框的角色多选：** 角色列表来自 `GET /roles`（`ROLE:MANAGE`）。读不到（403 或别的失败）时，角色字段关闭，字段下写明缺哪个权限码（`ROLE:MANAGE`，403）或读取失败加"重新读取"（别的失败）；编辑时字段下仍显示该管理员当前的角色名；这时不能改角色，更新请求照常重复他当前的角色（`PUT /admins/{id}` 必须带 `roleIds`）。
- **前端现状：** `src/pages/system/texts.ts:13-21,30-73`（原因表、`withScopeHint`、`withStateHint`、`protectedFailureText`）；译文 `src/locales/zh-CN/system.ts:20-29,34-39`（英文在 `src/locales/en-US/system.ts` 同名键）；`src/pages/system/AdminFormModal.tsx:84-86,97-99,251-285`（角色多选）。
- **检查顺序：** 契约 2392 行给出每个 `/admins` 路由的顺序；页面不依赖。
- **错误：** 上表；契约依据第 2392 行（403 的六个 `reason` 和 409 `INVALID_STATE` 的三个 `reason`）。
- **测试：** 表里九个值各一例，对话框保持打开、列表重读、文字是"码的译文 + 该句"；`reason` 缺失、`reason` 是不认识的值、`reason` 不是字符串三种情形只显示码的译文；一个操作被两个不同规则拦下时显示各自的句子；403 之后不跳转。
