## 二、立即修（1）

### 1. 后端拒绝客户端配置的"默认值"时，页面认不出来，管理员看不到是哪一项出错

- 位置：`src/pages/clientConfig/ClientConfigEditor.tsx:143-146`（`draft.some((entry) => entry.locale === detail.ref)`）；假后端 `mock/clientConfig.mock.ts:122,126` 和测试 `src/pages/clientConfig/editor.test.tsx:257` 都把默认值的 `ref` 写成空字符串 `""`；问题文件 `docs/contract-requests/2026-10-26-admin-frontend-notifications.md` 二.2 把"默认值的 `ref` 是空字符串"当作暂定做法去问后端。
- 契约怎么写：契约 §1.4（快照 `docs/shared-snapshots/backend-task-java-backend.md:111`）：“26.3 的 `PUT /client-config/{key}` 是语言标签，**不带语言的默认值（空字符串键）写 `default`**”。所以契约已经定了，后端会发 `ref: "default"`，不是空串，也不用去问。
- 触发步骤：以有 `CLIENTCONFIG:MANAGE` 的管理员打开 `privacyPolicyUrl`，改默认值，点保存，后端回 400 `INVALID_REQUEST`，`details` 为 `[{"ref":"default","reason":"NOT_HTTPS"}]`。我在拷贝里用 `tests/httpStubs` 的 `jsonResponse(400, envelope('INVALID_REQUEST', {details:[{ref:'default',reason:'NOT_HTTPS'}]}))` 复现。
- 错误结果：页签是 `["Default","ar","th","zh-Hans"]`，没有一个标"有错误"；抽屉里只有一行"Some input is not valid. Please check the fields and try again."，没有"后端没有接受，整个键没有保存"（`refused` 为假）；字段下没有原因；预览照常显示未保存的值。管理员不知道是哪一种语言、什么原因。
- 为什么是立即修，不是记录：这是协议被破坏（`ref` 的形式契约已经写明），而且落在页面自己选的主要路径上。页面按设计只检查类型（问题文件二.3），整数范围、文字长度、`inviteShareText` 占位符、`inviteLinkBase` 带查询这些限制全交给后端拒绝；而不按语言区分的键（`supportEmail`、`inviteLinkBase`、`drivingLookaheadMs`、`renderTierLocalMinFps`、`renderTierMaxMemoryMb`、`avatarCacheMaxMb`）只有默认值这一行，所以这些键上后端的每一次拒绝（例如 `OUT_OF_RANGE`）都会落到这个没有归属的状态。假后端和测试把错误形式固定成了 `""`，所以测试全绿也发现不了。保存没有写入，没有数据损坏。
- 建议的修法：页面把 `ref: "default"` 当作默认值那一行（保留对 `""` 的容忍也行）；假后端 `mock/clientConfig.mock.ts:122,126` 对空字符串键输出 `default`；`editor.test.tsx:257` 改成 `default`，并加一个断言"默认页签标有错误、字段下有原因"；问题文件二.2 改写成"契约 §1.4 已定为 `default`"。

## 四、变更（2）

1. 并发保存会静默删掉别人刚加的语言（实现者的变更候选，同意是变更，不是立即修）。我的理由，按 CLAUDE.md 的分类：
   - 页面做的正是契约和规格要求的：契约 §26.3 写"整体替换这个键的全部语言值"，规格 5.21 写"整个键作为一个整体保存"。后端没有"我读到的版本"字段，页面没有办法精确地防，所以这不是页面把对的事做错了。
   - 防它需要新的行为和机制：保存前再读一次比较，或者后端加 `expectedUpdatedAt`。这正是 CLAUDE.md 里"变更"的定义，要先把设计点给负责人确认（再读一次多一个请求且仍有时间窗；不同时的文字怎么写；是否改为向后端要字段）。
   - 损失有限、可恢复：丢的是一种语言的一个公开链接或文案，契约 §26.1 的审计写"改动前后的值"，可以从 `AdminAuditLog` 找回；触发需要两个管理员同时改同一个键。
   - 需要补一个事实，让负责人判断时不低估：窗口不是"保存瞬间的很小时间窗"。抽屉打开时用的是列表页**加载时**读的那一行（`src/pages/clientConfig/list.tsx:104,131`，`setOpen(row)`），打开时不重读，所以只要列表页开着，窗口就是从页面加载到点保存的整段时间（可能是几小时）。设计里应一并决定"打开编辑时重读这个键"。后端的 `expectedUpdatedAt` 请求已在问题文件二.4。
2. 预览由后端直接算（实现者的变更候选，同意）。页面按契约 §1.2 和 §26.1 的文字自己算（核对见不是缺陷 6），"列表里靠前"按标签字母序是页面的假设（问题文件二.7）。后端给预览接口后页面可以去掉自己的一份算法。

## 五、不是缺陷（6）

1. 发送弹窗按 Esc 或点"取消"丢掉写了一半的内容（实现者记录项 3，我改判）。位置 `src/pages/notifications/SendModal.tsx:299`（`onCancel`）。理由：遮罩已设成点不关（`mask={{ closable: false }}`，`SendModal.tsx:298`），这是本项目所有弹窗的统一做法（`src/components/ReasonModalForm.tsx:62`、短信、渠道、广告、版本等 20 多个弹窗同一写法）；Esc 和"取消"是有意的放弃；项目里没有"关闭前询问"的统一约定（任务 28 评审的不是缺陷 3 同一判断；只有审核规则页自己做了，那是页面离开而不是取消，任务 15 评审放在记录）。发送中 `onCancel` 是 `undefined`，不会在请求途中关掉。
2. 客户端配置抽屉按 Esc 或点关闭丢掉未保存的改动（实现者记录项 2，我改判）。位置 `ClientConfigEditor.tsx:204`。理由同上；这里同样 `mask={{ closable: false }}`（`:203`），保存中不能关（`:204`）。
3. 账号 ID 大小写不同当作两个 ID（`recipients.ts:25-33`）。理由：契约没有说账号 ID 是否区分大小写，页面也不该猜；按原样发出，如果后端不区分，后端对重复返回 400，整批不发、不写入，不会写错；这已在问题文件一.7 去问。
4. "重置"删除全部语言的值，与契约 §26.1"缺省语言可重置（删除该语言的行）"的出入。代码做的是规格 5.21 和任务书要求的、也是契约 §26.3 写的（"`reset`（删除该键全部行）"）：`ClientConfigEditor.tsx:229` 起的 `DangerConfirmButton` 行内确认删全部；§26.1 说的"删除一种语言的行"由"移除这种语言的值"加保存做到（`:355-362`，整体替换）。破坏性在确认之前写清楚了：确认句是"删除“X”全部语言的值？…"（`clientConfig.ts:64`），没有配置的键灰掉并写原因；确认句后半句的措辞问题见记录 4。
5. 加了语言页签却不填会挡住发送（`compose.ts:23-27`、`SendModal.tsx` 里 `submit` 对 `entryProblems` 的检查）。任务书写"其他语言选填"，这里的"选填"是可以不加这种语言：加了就要标题和正文都有，因为契约 §25.3 写"去掉空白后为空的值 → `INVALID_REQUEST`"；空语言没有被发成空字符串，页签标"有错误"，移除按钮就在同一页签里。
6. 预览的回退顺序与契约一致，没有出入。`preview.ts:44-80` 对照契约 §1.2 和 §26.1：先完整匹配（不区分大小写）→ 主语言子标签相同的条目，只有一个就取它 → 多个时取"是请求标签前缀"的 → 再按文字变体（显式 `Hans`/`Hant`，只对 `zh` 推断，`TW`/`HK`/`MO` 取 `Hant`，其余 `Hans`）→ 取靠前的第一个 → 该键不带语言的默认行 → 登记的默认值 → 未配置；不按语言区分的键不看语言行；`false`、`0`、空文字算值。我抽了变异 R18、R22、R30（跳过登记默认值）、R38（预览不用未保存的草稿），都被杀死。页面只算一个请求语言（预览里选的那个），契约是逐项尝试 `Accept-Language`，这是预览的合理简化。
