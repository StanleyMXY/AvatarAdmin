## 做了什么

- `src/services/auth/`：`login`、`enrollTotp`、`changePassword`、`getMe`（字段缺失按缺失处理）、`getAdminMeta`（任何失败得到空对象）和 `AdminMeta` 类型（20 个字段）。密码原样发送，不去空白、不哈希；只有用户名去首尾空白。
- `src/session/`：`safeReturnUrl`（只收站内路径；`//host`、反斜杠、编码形式、控制字符、登录页自己都回 `/dashboard`）、`loginUrl`、`gateFor`（哪个状态去哪个地址）、`pendingEnroll`（绑定令牌只在内存）、`loadSession`（读 `/me`，不在改密码状态时再读 `/meta`）、`useSession`、`SessionBridge`（把请求层的两个信号接到页面）、`SessionGate`（外壳和 403 页的门）。
- 页面：登录（验证码框在 `ADMIN_TOTP_REQUIRED` 后才出现，验证码错清空，429 说几分钟后再试）、绑定认证器（二维码在浏览器里生成，不向任何外部地址发请求，刷新后回登录页）、强制改密码（只允许这一页；长度按码点数；旧密码错放在旧密码框旁）、顶栏头像菜单的改密码对话框。
- 会话：401 `ADMIN_INVALID_TOKEN` 清令牌、标签、内存里的账号，带回跳地址去登录页，原请求不会重发；403 `ADMIN_FORBIDDEN` 只提示并重读一次 `/me`，不跳转、不轮询。`src/app.tsx` 的 `getInitialState`、`innerProvider`（Umi 的数据层里、路由外）和外壳里的门都是这个任务接上的。

## 红到绿

先写测试，模块不存在时全部因"模块不存在"失败；绿：任务 7 相关 76+ 个测试。全量 1326 个测试（含任务 8 之前的）在提交时通过；`tsc --noEmit` 退出 0；`biome check .` 无输出。

**真实浏览器（Playwright 对 `npm run dev:mock`）发现并修掉两个单元测试看不到的缺陷：**登录后被弹回登录页（Umi 把账号提交到新挂载的页面晚一拍，门在那一拍里看到"没有账号"）；绑定成功后被弹回登录页（页面把"绑定令牌已清空"当成"没有可绑定的东西"）。前者的修法是 `useGoWhenSignedIn`（账号进了状态才跳转），后者是页面只读一次绑定令牌。评审者又在真实浏览器里把这两处各拿掉一次，确认它们真的需要。

## 评审（深度，一轮）

评审者的结论：立即修 0、记录 17、变更候选 2、不是缺陷 6。令牌（内存加 `sessionStorage`，不在 `localStorage`、地址、日志）、回跳地址（17 万个输入没有一个能离站）、路由守卫（33 个"路由乘状态"组合没有绕过）、会话信号、防重复提交、各登录分支都没有找到需要立即修的缺陷。

我对其中 11 条做了处理，都已修并有测试（变异检查确认测试会变红）：

- 绑定令牌过期（401）被当成登录会话过期：用户同时看到两条矛盾提示，标签列表被清掉。**已修**：这一个请求不通知会话层（`apiRequest` 的 `reportSession: false`）；绑定过期回登录页时保留回跳地址。
- 令牌在读 `/me` 和 `/meta` 之间失效：外壳照常显示但令牌已清，之后全部 401 且不再跳转。**已修**：令牌被清掉就不建立会话，并清标签。
- 启动时发现旧令牌只跳登录页、不清标签，下一个管理员会继承上一个人的标签路径。**已修**（同上）。
- 三个同时到达的 403 弹三条相同提示。**已修**（同一个 `key`，antd 只显示一条）。
- 登录页、绑定页、改密码表单的提示条存的是译好的字符串，切换语言后停在旧语言。**已修**：存键或失败本身，渲染时翻译。
- 英文"1 minutes"。**已修**（ICU 复数）。
- 服务器没发 `username` 时顶栏菜单整个不渲染，没有退出入口。**已修**。
- 登录页路径对大小写、末尾斜杠、`#`、`//`、`/./` 不敏感：已登录者打开 `/USER/CHANGE-PASSWORD` 看到强制改密码页；回跳地址能把已登录的人送回登录表单。**已修**（`normalizePath`）。
- 必须改密码的账号在壳里短暂看到布局和菜单分组。**已修**：`canAccess` 对这类账号一律为假。
- 测试缺口：`useGoWhenSignedIn`（Umi 晚一拍，桩加了 `setTestInitialStateDelay`）、`refreshPermissions`、`useSubmitOnce`、`getAdminMeta` 非对象、登录页把回跳地址交给绑定页、退出时清待办绑定。**已补**。

## 仍然记录的 6 项（建议全部修）

1. 壳外框的瞬态：未登录时短暂存在没有菜单项的布局外框（评审者用 MutationObserver 看到，没有页面内容泄露，没拍到肉眼可见的一帧）。模块页面接入菜单后要在真实浏览器里再看一次。
2. 登录请求在 `sessionStorage` 里已有仍有效的令牌时会带 `Authorization` 头（`apiRequest` 没有"匿名"开关）；真后端对登录接口收到这个头的处理没有验证。
3. 绑定页的二维码下没有"无法扫描"的备用办法（规格 3.2 只要求二维码）。
4. 强制改密码页没有退出登录入口（规格 3.3 没有要求，列为变更候选）。
5. 已登录的人打开 `/user/login` 看到的是登录表单，不会被送走（规格没有要求，列为变更候选）。
6. `/user/enroll` 页和登录页对 429 之外的错误文字相同，但绑定页没有"请 N 分钟后再试"之外的提示变体（现已共用 `failureNotice`，只是没有各自的文案）。
