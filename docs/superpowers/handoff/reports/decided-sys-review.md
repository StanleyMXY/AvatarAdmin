## 发现（每条一个分类）

### 记录（12）

1. **键名叫 `code` 的字符串不遮，和决定列出的敏感词"code"不完全一致。** `auditDetail.ts:103-115`（`isCredentialKey`：`code` 只在和 verify、sms、mfa 等词同在一个键名里才算）；测试 `auditDetail.test.ts:46-54` 把 `code: 'USER:VIEW'` 明确写成不遮。触发：后端写一条详情 `{"code":"483920"}`（短信验证码）。结果：页面显示 `483920`。这是实现者为了不遮权限码做的取舍，报告里写了做法但没有把它标成对决定的偏离。要触发它，后端得违反"不把凭据写进详情"，所以我没有判成立即修；如果负责人认为决定的"code"就是任何叫 code 的键，应改判立即修。建议：键名正好是 `code` 且值是 4 到 10 位纯数字的字符串时遮（权限码 `USER:VIEW` 不是纯数字，不受影响），加测试。
2. **自由文本里被转义的引号会漏出一段，转义的 JSON 整段不遮。** `auditDetail.ts:200-206`（`TEXT_PAIR` 的 `dq` 分支 `[^"]*` 遇到 `\"` 就停）。触发：详情字符串是 `Request body: {"user":"bob","password":"hun\"ter2"}`。结果：显示 `"********"ter2"}`，密码的后半段漏出；详情字符串是 `{\"password\":\"hunter2\"}`（被再转义一次）时整段原样显示。
3. **"设置名是凭据"这条规则只认固定的几个字段名，也不往嵌套里走。** `auditDetail.ts:117-150`（`LABEL_KEYS`、`VALUE_WORDS`、`namesCredential`）。触发：详情 `{"configKey":"facebook.access_token","value":"EAAB..."}`，或 `{"setting":"sms.api_secret","changes":{"from":"x","to":"y"}}`，或 `{"k":"facebook.access_token","v":"…"}`。结果：值原样显示。契约只写了详情"记改动的字段名和新旧值"，没有写形状，所以这是尽力而为的第二道线；后端不写凭据仍是第一道。
4. **自由文本里没有分隔符的写法、和几种常见的凭据键名不遮。** `auditDetail.ts:34-101`、`:178-224`。触发：`changed password to hunter2`、`password hunter2`、`pass=hunter2`（JSON 键 `pass` 会遮，文本里不遮）、`PIN 1234`、`otp 123456`、`verification code 123456`、`jwt=eyJ…`、`Bearer abc`（单独一个）、`password=a b c`（只遮第一个词）；键 `jwt`、`session`、`sessionId`、`accessKey`、`sig`、`salt` 的字符串值也不遮。
5. **自己那一行的原因小字很占地方，对比度不到 AA。** `admins.tsx:225`（`Typography.Text type="secondary" style={{ fontSize: 12 }}`）。触发：用 root 打开管理员页（真实浏览器，英文，1500 像素宽）。结果：root 那行高 303 像素，其他行 57 像素，五句原因叠在一起；字色是 antd 的 `type="secondary"`（透明度 0.45），12 号字，我算出对比度在暗色下 4.09:1、浅色下 3.35:1，低于决定对正文要求的 4.5:1（`modes.ts` 里的 AA 色 `colorTextSecondary` 没有被 `type="secondary"` 用到）。按钮被禁用的原因是用户唯一的线索，建议用 AA 的次要文字色、并把"停用或删除"那两条合成一句。
6. **过时的注释。** `PermissionTreeSelect.tsx:34-36`（"a parent with only some of its descendants checked shows half checked and is not in the value"）。触发：读注释，再勾一个功能：页面码进值里、页面显示全勾，不是半选。`permissionTree.ts` 的函数说明是新的，这一处没有同步。
