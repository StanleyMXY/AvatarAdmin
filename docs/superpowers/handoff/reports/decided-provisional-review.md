## 二、记录（2）

### 记录项 1. 日报、通话质量的"今天"在每次渲染时取当前时间，页面跨过 UTC 零点后，昨天那一天会在数据没刷新的情况下失去"临时值"标记

- 位置：`src/pages/stat/daily.tsx:77`、`src/pages/sessions/quality.tsx:130`（`const today = todayUtc();`）。总览用的是读数据那一刻的 `window.to`（`overview.tsx` 的 `data.today`），不受这个影响，三处做法不一致。
- 触发步骤：UTC 23:58 打开日报（或通话质量），范围含今天，昨天（刚过去的这一天）带"临时值"；等到 UTC 00:02，点一下"明细"页签（任何会重新渲染的操作都行）。
- 错误结果：这一天的"临时值"标记、图下说明、空心点都消失，但表里的数字还是 23:58 时读到的、没过完的数字，没有重新读取。把没数完的数字当成完整日的数字看。这一步我只读了代码，没有在浏览器里跨零点复现。
- 为什么是记录：只在页面一直开着跨零点时出现，刷新就恢复，数字本身没有错，只是标记晚了。建议修：和总览一样，在读数据时记下"今天"，用它判断。

### 记录项 2. 总览卡片里"为什么是灰色"的说明只写在 `title` 属性上，触屏和键盘用不了

- 位置：`src/pages/dashboard/OverviewCard.tsx:42`（`title={…'stat.common.provisional.changeTip'…}`）。同一处的"临时值"标记用的是 antd 的悬停提示，不是这个问题。
- 触发步骤：手机或触屏上打开总览，看"较昨日 +65.6%"为什么是灰色。
- 错误结果：没有任何办法看到说明（`title` 不在触屏上弹出，也不能用键盘聚焦）。页头那句"今日数据是临时值"在，所以灰色不至于没有解释，只是这一条逐项说明丢了。建议修：改成和标记一样的 `Tooltip`，并让它能聚焦。

## 四、不是缺陷

1. **实现者的记录项 3（总览趋势图实线和虚线可能各用各的比例尺）不成立。** 位置 `src/pages/dashboard/trendChart.ts` 约第 76–127 行。依据：总览日活今天 1272、上周同一天 802，浏览器里两点的像素高度之比等于 1272:802（0.633 对 0.630），而同一条线性比例尺从 0 起，只有两条线共用同一把比例尺像素比才等于数值比。放在同一个坐标轴上的"近 7 天"图里，虚线 1500 的峰值也没有越出或顶满轴。`scale: { y: { key: group } }` 起了作用。建议把报告里这一条删掉，免得后面有人去改它。
2. **涨跌照写数字、只换灰色。** 决定的两句话放在一起只有这一种读法能成立（第二句"涨跌用灰色"以涨跌还显示为前提）；总览的卡片只有"今天对比前一天"这一种比较，不写就没有信息。实现者已经写明改成破折号只是 `changeText.ts` 里一行。保留。
3. **总览趋势图没有"空心点是临时值"的说明句，日报和通话质量有。** 决定没有要求；总览页头已有"今日数据是临时值，每隔 N 分钟刷新一次"。不是缺陷。
4. **"今天"取浏览器时钟的 UTC 日期，不取后端时间。** 和现有 `utcDay.ts` 一致，后端没有提供服务器时间字段（我在 `docs/backend-inputs` 和 `docs/contract-requests` 里搜了 `serverTime` 一类的名字，没有）。浏览器时钟偏差一天以上时标记会错，需要不可能的假设，不是缺陷。
5. **日报里今天没有行时趋势图画成空心的 0。** 规格 4.4 要求趋势图缺日补 0，已有的差异，实现者已写。
